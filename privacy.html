Privacy policy · Updated 2 November 2026

Data stays under the owner's control.

This policy describes the personal Windows application Timo Cartoons Local and its information website. The application is intended only for its owner's channels. It does not accept public registrations.

Google permissions and use

If the owner authorizes Google access, the application requests youtube.upload to upload reviewed cartoons and youtube.readonly to verify that the connected YouTube channel matches the configured owner channel. The read permission is broader than the channel-identity check performed by this application. The current client does not make API calls to retrieve watch history, subscriptions, or private playlists.

The application receives authorization credentials, channel identity information, and upload responses such as video identifiers and processing results. It uses them to verify the destination, upload the selected file, report the result, and avoid duplicate uploads. It does not intentionally use Google user data as input to cartoon generation or model training.

Optional Instagram connections

If the owner separately enables Instagram publishing, the local adapter verifies the intended Instagram username and its linked Facebook Page or business portfolio, creates a Reels container, transfers the selected local video to Meta, and publishes it after processing. It stores connection credentials encrypted on the owner's computer and keeps a local operation journal. Some Meta connection routes require a broader messaging permission; that choice must be reviewed by the owner. The current adapter does not call message-reading or message-sending endpoints.

Local storage

Videos, soundtracks, scene files, review records, and job logs are stored on the owner's Windows computer. Google authorization tokens are encrypted for that Windows user with DPAPI and protected file permissions. Upload journals store operation state; resumable session addresses are encrypted. The application never requests a Google password in chat and is designed not to print tokens or authorization codes.

Sharing and processors

The local upload client sends the chosen video, its metadata, and required authentication to Google's official endpoints. Videos marked public become available through YouTube according to the owner's settings. The application has no advertising or data-sale feature.

The owner may operate the application with ChatGPT/Codex. In that case, task instructions, public channel identifiers, publication links, and non-secret task status can be processed in that ChatGPT session under the owner's OpenAI account settings. OAuth tokens and private client configuration are not intended to be included in chat.

The application's use and transfer of information received from Google APIs must follow the Google API Services User Data Policy, including its Limited Use requirements.

Retention and control

Local artifacts remain until the owner removes them. The owner can stop scheduled runs, disable publishing, and revoke the application's Google access at Google Account connections. Revoking access stops future authenticated requests; it does not delete videos already published. Those videos are controlled separately in YouTube Studio.

This website

These pages do not add analytics, advertising, sign-in forms, or tracking cookies. If hosted on GitHub Pages, GitHub may collect technical request information, including visitor IP addresses, under the GitHub Privacy Statement.

Contact and changes

The owner can be contacted through the project issue tracker or the public YouTube channel. Do not include passwords, tokens, or private account data in a public issue. This page will be updated if the application's data handling changes.
